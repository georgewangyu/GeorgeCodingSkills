# GeorgeCodingSkills

Agent skills for coding work, each tagged by how likely it is to survive better models.

## Skills

| Skill | What it does |
|---|---|
| [`start-playbook`](skills/start-playbook/SKILL.md) | Start here. Maps the task to the right skill in lifecycle order (define, plan, build, verify, review, ship) and sets the always-on behaviors. Adapted from [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills) `using-agent-skills`. |
| [`grill-me`](skills/grill-me/SKILL.md) | Interviews you until the intent, or every decision in a plan, is settled. Rounds with a recommended answer per question, facts looked up by the agent, explicit-yes gate. Combines [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills) `interview-me` and [mattpocock/skills](https://github.com/mattpocock/skills) `grilling`. |
| [`brainstorm`](skills/brainstorm/SKILL.md) | Turns a rough idea or an open "how should we build X" into a decision: ground first, challenge premises, 4 to 6 options across axes, prune to 2 or 3 with pros, cons and a cost check, optional bakeoff, decision note with a Not Doing list. Combines [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills) `idea-refine`, [obra/superpowers](https://github.com/obra/superpowers) `brainstorming`, [garrytan/gstack](https://github.com/garrytan/gstack) `office-hours`, [EveryInc/compound-engineering-plugin](https://github.com/EveryInc/compound-engineering-plugin) `ce-ideate` / `ce-bakeoff` / `ce-pov`, [pstack](https://github.com/cursor/plugins/tree/main/pstack) `sharpen` / `arena` and [mattpocock/skills](https://github.com/mattpocock/skills) `prototype`. |
| [`spec-driven-development`](skills/spec-driven-development/SKILL.md) | Writes down what we are building before building it. Brief by default: goal, a done check that can fail, proof wanted, what we know, constraints, out of scope (also the format for worker briefs). Full mode only when earned (one-way doors, multi-PR work, cross-team review, a new service or API): scope check, boundaries, user stories, test seams, a design contract for multi-PR work, normal and blind review. Combines [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills) `spec-driven-development`, [mattpocock/skills](https://github.com/mattpocock/skills) `to-spec`, [obra/superpowers](https://github.com/obra/superpowers) `writing-plans`, [garrytan/gstack](https://github.com/garrytan/gstack) review lenses, [EveryInc/compound-engineering-plugin](https://github.com/EveryInc/compound-engineering-plugin) `ce-plan` and the [pstack](https://github.com/cursor/plugins/tree/main/pstack) guide. |
| [`planning-and-task-breakdown`](skills/planning-and-task-breakdown/SKILL.md) | Turns a spec into ordered vertical slices that each end green, one slice per PR, ticket and worker brief. Brief by default: goal, a done check that can fail, how to verify, blocking edges (deploy edges too), files, size. Full mode for a multi-PR series, rollout ordering or work bigger than one session: design contract, interfaces, rollout table, decision list. Never overwrites an unfinished plan; tickets and workers are offered, never automatic. Combines [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills) `planning-and-task-breakdown`, [mattpocock/skills](https://github.com/mattpocock/skills) `to-tickets` and `wayfinder`, [obra/superpowers](https://github.com/obra/superpowers) `writing-plans` and `executing-plans`, [EveryInc/compound-engineering-plugin](https://github.com/EveryInc/compound-engineering-plugin) `ce-plan`, [garrytan/gstack](https://github.com/garrytan/gstack) `plan-eng-review` and [pstack](https://github.com/cursor/plugins/tree/main/pstack) `principle-sequence-verifiable-units`. |
| [`incremental-implementation`](skills/incremental-implementation/SKILL.md) | Builds a plan one slice at a time. Each slice ends in a PR revision with green CI and a passed done check, then a fresh-context review before the next slice. Fresh worker or subagent per independent slice, rule 0 simplicity, scope discipline (log, do not fix), safe defaults, a capped fix loop, rulings instead of stalls, the plan index as the ledger. Combines [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills) `incremental-implementation`, [obra/superpowers](https://github.com/obra/superpowers) `subagent-driven-development` and [pstack](https://github.com/cursor/plugins/tree/main/pstack) `principle-sequence-verifiable-units`, `principle-laziness-protocol` and `principle-subtract-before-you-add`. |

Combines [addyosmani/agent-skills](https://github.com/addyosmani/agent-skills) `source-driven-development` and [mattpocock/skills](https://github.com/mattpocock/skills) `research`. |

## Bitter-lesson tags

Each skill marks its parts with a short inline tag:

- `[bl: invariant]`: a rule of the game (a feedback signal, an eval, or a real invariant). Always follow.
- `[bl: strong]`: follow it. It should become a hard check or a learned example over time.
- `[bl: soft]`: guidance for weaker models. A strong model may skip it. Candidate to expire.

A `BITTER_LESSON.md` next to each `SKILL.md` holds the full analysis (why, review date, delete-when, ablation result). Agents only read it when evaluating skills, not at session start.

```sh
python3 skills/principles-bitter-lesson/scripts/bitter_lesson.py check  --root .   # every tagged item has a row, and the reverse
python3 skills/principles-bitter-lesson/scripts/bitter_lesson.py report --root .   # the cleanup list
python3 skills/principles-bitter-lesson/scripts/bitter_lesson.py ablate --root .   # soft items to test with and without
```

Principle skills (`principles*`) are durable reasoning methods and carry no tags.

Expire by evidence: run the skill's eval with and without a soft item on a new model. If nothing changes, delete it. A skill whose items have all expired goes away.

## Install

Copy a skill folder into your agent's skills directory (for example `~/.claude/skills/`).
